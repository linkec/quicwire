# 多连接冗余设计与配置

2026-10-03。用户确认：最多 N 条已认证连接全部建立并探测，其中 K 条双向同包多发，对端去重。本次仅同一服务端实例的多个 IP/UDP 端口入口，不包含跨服务端聚合、带宽分流、多 peer 或第三方路由。

## 配置与约束

客户端新增 endpoints（IP:端口或范围的数组）、max_sessions、active_sessions、standby_rotate_secs；服务端新增 listen（IP:端口或范围的数组，省略 IP 的纯端口范围默认绑定 0.0.0.0）。保留旧 endpoint/bind 的单连接写法。新旧同类字段同时出现时报错，避免静默覆盖。端口为 1–65535，每组最多展开 256 个地址；总连接上限 32，激活数为 1..max_sessions。候选地址按 IP 交错，先覆盖 IP；每个候选端点最多一条连接。实际数目不足时显示降级。客户端 bind 限制所选外层地址族，IPv6 使用 [地址]:端口。

## 协议

0.3 使用 ALPN h3、真实 HTTP/3 SETTINGS/QPACK/Extended CONNECT，私有 :protocol=quicwire 承载复制去重帧。此扩展头在加密请求中，不出现在 ClientHello。不能把带序号的私有数据伪称为 RFC 9484 原始 IP 格式；0.2 的 CONNECT-IP 仍有独立协议测试，但 0.3 守护进程要求新的隧道协议，两端需一起升级。

HTTP Datagram Quarter Stream ID 后跟 Context 0，随后是私有消息类型及负载。身份认证继续固定 Ed25519 公钥。认证后的 HELLO 绑定客户端随机 128 位运行标识、随机 64 位路径标识、N/K；应答绑定服务端随机 128 位运行标识。不同运行代际不能混用去重状态或激活集合。旧连接不能覆盖新代际，控制消息只在已绑定连接上接受。

数据消息包含每发送方向独立递增的 64 位包序号及原始 IP 包。所有副本共享同一个序号，接收端按运行代际使用固定 65536 包的滑动位图去重。验证地址和长度后才推进窗口；窗口内乱序交付一次，窗口外迟到包丢弃，不等待慢副本。计数器分别记录唯一业务包、副本、重复、过旧、无连接、无效和队列丢弃。

## 调度与探测

### 0.3.2：启动顺序、评分阈值与稳定会话 TTL

0.3.2 修正 TTL 质量判断方向：即使当前路径最好，只要最佳备用稍差且未超过容忍上限，也会轮换。配置项改为 `ttl_max_degradation_percent`；0.3.1 的旧字段 `ttl_degradation_percent` 须手动改名，不接受旧字段，避免把旧语义静默沿用。

客户端启动时按配置展开后的会话槽位顺序激活前 K 条健康连接，不按最低 RTT 或最快完成握手排序。多 IP 沿用地址交错展开规则。等待前 K 个槽位认证及探测，最多 10 秒；缺失时按槽位顺序使用已健康连接并显示不足。开始传输后进入正常质量选路，保留 5 秒最短保持与 3 秒连续改善观察。

| 客户端参数 | 默认值 | 含义 |
|---|---:|---|
| `switch_threshold_percent` | `20.0` | 候选激活组评分总和相对当前组严格改善超过此百分比才质量切换；范围 `[0,100)`，0 仍要求严格改善。示例使用 5.0。 |
| `stable_session_ttl_secs` | `300` | 稳定会话从认证注册起算的总存活软期限；0 关闭，其他为 5–86400 秒。激活不重置总年龄。 |
| `ttl_max_degradation_percent` | `10.0` | TTL 接替备用的评分最多允许比当前会话高此百分比；0 仅允许相等或更好，范围 0–1000。 |
| `reserve_sessions` | `1` | 预留评分最好的健康备用数量，范围 0–32，实际数量受可用备用数限制；0 不预留。 |

例如普通阈值 5% 要求候选组评分严格低于原组的 95%；TTL 最大容忍劣化 10% 要求备用评分不超过当前会话的 110%。普通切换寻找明显改善，TTL 则允许有限性能退让来刷新五元组；两者用途不同，普通质量切换不必等待 TTL。默认普通阈值保留旧值，部署可显式降低。

TTL 到期后持续复查，最佳健康备用比当前差太多则延后，不关闭会话、不重置年龄。健康接替候选需至少有 3 秒连接观察；缺少合格备用同样延后。多个激活会话过期时逐个检查，较早但无合适接替者的会话不会挡住其他已有合适备用的会话。没有备用名额（例如 N=K）时，监控给出延期原因。

交接顺序为：更新激活集合及控制版本 → 新集合开始发送 → 至少一条健康激活连接确认服务端已应用当前版本，且 K 条激活连接均健康 → 关闭旧会话并重新建连、更换源端口。等待确认期间保留旧会话；候选失效时允许回退到旧会话。一次仅退役一条，轮转间隔至少 2 秒。

预留候选不受普通 `standby_rotate_secs` 期限影响，未达到质量切换门槛的较快候选也能留给 TTL 接替。预留会话到达稳定 TTL 后，只有存在质量在容忍范围内、且至少观察 3 秒的其他健康备用才重采样；其他备用差太多则保留。非预留候选继续普通轮转。预留数量越大，探索新五元组的名额越少。

监控新增各策略参数、预留数量、TTL 轮转次数、启动待选、TTL 延期原因；每条路径增加评分、配置槽位、预留/等待交接标志和稳定 TTL 剩余秒数。TTL 显示 0 表示到期，不代表无条件关闭。上述扩展不改变 H3 数据帧，0.3.2 与 0.3.0/0.3.1 可互通；使用新配置的客户端须升级，策略只在客户端配置。

客户端管理激活集合；探测消息携带单调递增的集合版本及路径 ID 列表，所有连接每 500 ms 重复发送，服务端确认已应用版本。两端各自发起探测，支持同时匹配多个未决响应，RTT 大于单个探测周期时不会覆盖旧 nonce。旧版本不覆盖新版本；单次控制报文丢失由下次探测修复。无响应 1.5 秒不可用，连接关闭立即移除；新路径须完成探测后才有资格激活。空闲备用也探测。客户端依据探测 RTT、波动和近期探测超时选路；质量替换需持续改善和最短保持时间，故障替换绕过滞后。已进入观察的候选只要仍健康且持续满足改善阈值，就保留其观察时间，不因同级备用排序波动反复清零；轮转避开这组候选，最多等待当前 3 秒观察结束。

每条路径独立、有界发送队列。快路径不会等慢路径；某条队列满时可丢弃该路径副本，其他路径照常发送并报告实际冗余不足。全部队列满才对 TUN 施加背压，切换/关闭可打断等待。所有路径断开时丢弃新业务包，重连退避有界。不把成功入队当作到达对端。

## 备用轮转

本节指普通备用周期，预留候选免于此周期；激活及预留会话的稳定 TTL 见上一节。

用户补充：非激活连接不能永久停留在原五元组。standby_rotate_secs 默认 180，指连续非激活时长；激活时清除，退出激活后重新计时。0 关闭，其他允许 5–86400 秒。每次仅轮转一条，轮转之间至少间隔 2 秒；激活路径不因到龄被关闭。N=K 且所有路径激活时没有备用槽位，不执行轮转。

每个客户端连接独立 UDP socket，重连时由系统分配新源端口，并明确拒绝重复使用该槽位上次端口；启用轮转时 bind 必须使用端口 0。槽位有多个候选端点时，每次重新连接也前进到下一个候选。先关闭旧备用，再建立新备用，避免超过 N；此期间总连接数短暂低于 N。新路径经认证和探测后参与选路。新五元组不保证网络一定选中更短线路，仍以测量判断。

## 监控

本机 quicwire status --config ... 输出整体与每路径状态，支持 --json。通过受文件权限限制的本地 Unix socket 读取快照，无网络管理 API。显示配置/实际 N/K、降级原因、端点、连接时长、连续备用时长、轮转次数、探测 RTT/波动/超时、QUIC 累计丢包估计、业务/副本计数、重复丢弃、队列丢弃和切换原因。QUIC 丢包不等于内层业务丢包。额外读取 TUN 的内核 tx_dropped/rx_dropped，区分包进入 QW 前的内核队列丢弃与进入复制逻辑后的路径损失。

同 IP 不同端口不保证物理路由独立。K 副本约消耗 K 倍数据带宽，无法保证共享瓶颈或所有路径丢包时零丢包。

## 使用

完整配置见 examples/client.toml 与 examples/server.toml。原 endpoint/bind 单连接配置仍可解析，但二进制双方必须升级到 0.3。启用多端口后需要允许配置的全部 UDP 端口。

```sh
sudo quicwire status --config /etc/quicwire/quicwire.toml
sudo quicwire status --config /etc/quicwire/quicwire.toml --json
```

状态 socket 位于 /run/quicwire，以网络命名空间编号和 TUN 名称区分，权限 0600、父目录 root 所有且不可被其他用户写入。systemd 示例通过 RuntimeDirectory 授权该路径在 ProtectSystem=strict 下可写。当前运行方式为 root；状态命令也需相应权限。
