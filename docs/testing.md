# 基础隧道实测记录

日期：2026-10-02。测试源码提交：`d65e7f5`。范围为 Linux 单路径 IPv4 QUIC + TUN；不代表完整多路径验收已经完成。

## 构建与协议验证

- 本地 macOS：格式检查、Clippy（warnings 视为错误）、9 项测试通过。
- [Linux CI](https://github.com/linkec/quicwire/actions/runs/37009923531)：相同检查、9 项测试、release 构建及真实 TUN namespace 测试全部通过。
- 两台测试机部署同一份 CI 二进制，SHA-256 均为 `e008b3db4bb7ec0167c642a1799efd6ef1a7ec0770555690380ff03930140780`。

9 项测试覆盖双向公钥握手与 DATAGRAM、未知客户端公钥、错误服务端公钥、仅复制公钥而无对应私钥的冒用、两端配置不匹配、超长控制消息、密钥文件权限与防覆盖、非法配置、IP 包长度与地址校验。

Linux namespace 测试通过真实 TUN 发送双向 ICMP，验证 MTU 1100 的边界、SIGTERM 后接口清理及服务端重启后客户端自动恢复。可运行 `sudo bash scripts/linux-smoke.sh target/release/quicwire` 重现。

## 双机环境

在同一台 PVE 宿主机上新建两台专用 Ubuntu 24.04 VM，各 2 vCPU、2 GiB 内存、32 GiB 虚拟磁盘，内核 `6.8.0-134-generic`，使用 VirtIO 网卡和同一虚拟网桥。两端通过 systemd 运行 quicwire，独立生成私钥，仅交换公钥。

隧道地址为 `10.77.0.1/30` 和 `10.77.0.2/30`，MTU 1100，其他传输参数采用默认值。公开文档省略内部管理地址、SSH 信息及部署凭据。

## 结果

| 场景 | 方法 | 实测结果 |
| --- | --- | --- |
| 客户端 → 服务端 ICMP | 100 包，间隔 20 ms | 100/100，0% 丢包，平均 RTT 1.351 ms |
| 服务端 → 客户端 ICMP | 100 包，间隔 20 ms | 100/100，0% 丢包，平均 RTT 1.282 ms |
| MTU 正常边界 | ICMP payload 1072，DF，10 包 | 10/10，完整 IP 包为 1100 字节 |
| MTU 超限 | ICMP payload 1073，DF | 本机拒绝，提示 `message too long, mtu=1100` |
| 外层直连 TCP 基线 | iperf3 单流，10 秒 | 接收端 13.566 Gbps，无重传 |
| 隧道 TCP 客户端 → 服务端 | iperf3 单流，10 秒 | 接收端 197.031 Mbps，发送端重传 517 次 |
| 隧道 TCP 服务端 → 客户端 | iperf3 单流，10 秒，`-R` | 接收端 200.989 Mbps，发送端重传 581 次 |
| 隧道 UDP 客户端 → 服务端 | 10 Mbps，1000 字节，10 秒 | 接收端 9.997 Mbps，iperf3 报告 0% 丢包 |
| 隧道 UDP 服务端 → 客户端 | 相同条件，`-R` | 接收端 10.000 Mbps，iperf3 报告 0% 丢包 |
| 文件完整性 | 经隧道 HTTP 传输 64 MiB 随机文件 | 两端 SHA-256 一致 |
| 正常停止 | SIGTERM，经 systemd 停止服务端 | `qw0` 随进程退出删除 |
| 服务端重启 | 停止、确认接口清理、启动 | 客户端自动恢复，启动命令返回后约 1.770 秒首次 ping 成功 |
| 客户端重启 | systemd restart | 命令返回后约 0.297 秒首次 ping 成功 |
| 外层 UDP 阻断 | 仅服务端 VM 阻断来自客户端的 UDP 4433，持续至少 12 秒 | 隧道 ping 失败，日志确认连接超时；撤除规则后自动重连，约 0.289 秒首次探测成功 |
| 错误服务端公钥 | 客户端换成无关公钥并重启 | TLS 明确拒绝；ping 失败，收发数据计数为 0 |
| 恢复正确公钥 | 还原配置并重启客户端 | 自动恢复，约 0.283 秒首次 ping 成功 |

文件 SHA-256：`a1d38f58aa117945512c2723942d51fa2dda89962b4d126c4d28473d3b515fb5`。

恢复时间为本次自动化从启动/恢复命令返回，到一次成功 ping 的墙钟时间，包含 SSH 与探测调度开销。每项仅测一次；断网测试的计时从撤除规则后开始，不包含阻断期间的超时检测过程。这些数字不是故障检测上限或无损切换承诺。

测试完成后已撤除临时阻断规则、停止 HTTP/iperf 测试服务，两端 quicwire 保持运行；系统默认路由保持在各自原有外层网卡上。两台 VM 保留，VM 本身不设宿主机开机自动启动；VM 内的 quicwire 服务已启用自启动。

## 性能与覆盖限制

以上是同宿主机短时测试，未注入常态丢包和高 RTT，不能用于推断公网、跨境、蜂窝网络或多路径收益。吞吐数据为单次结果，尚无长期稳定性、持续资源占用或统计分布测试。

饱和 TCP 测试观察到有界发送队列丢包；客户端队列满计数达到 517，与该方向 TCP 重传数一致。当前优先完成基本功能，尚未针对吞吐和队列参数优化。不能把 10 Mbps UDP 下的零丢包延伸为任意负载下的零丢包保证。

本轮没有覆盖内层 IPv6、路由子网、NAT、多 peer、多路径、移动端、QUIC 外层 IPv6 实网、公网抗拒绝服务及长期运行。以上能力仍以需求和后续设计为准。
