# 实施顺序

以下为计划，除工程初始化外均未完成。

## 0. 工程初始化

- Rust 包、命令行入口、固定工具链与锁文件。
- 需求、技术选型记录及构建检查。
- 公共仓库不包含部署凭据或真实密钥。

## 1. 路径测量与协议规格

- 对客户端到核心的候选路径量测至少 24 小时，覆盖拥塞时段。
- 比较 RTT、丢包相关性、路径共享瓶颈与有效容量。
- 定义身份认证、BIND、session 生命周期、SET/epoch、REPORT 和数据包格式。
- 审查重放、跨 peer 路径注入、资源耗尽及密钥撤销行为。
- 确定 HTTP/3、CONNECT-IP 的首版范围。

通过条件：候选路径有可测的独立性收益，协议字段与状态机能够指导实现。

## 2. 单路径原型

- Linux 两端完成公钥认证、TUN 收发和 QUIC DATAGRAM 转发。
- 验证未知 peer 拒绝、撤销、MTU 处理和有界内存。
- 建立单路径 CPU、内存、每秒包数、有效吞吐及延迟基线。

通过条件：单路径可持续传输，异常输入与网络失败不会破坏进程状态。

## 3. 多路径冗余

- 增加 session 绑定、K 份复制、接收端去重、独立路径队列。
- 测试重复、乱序、旧包、路径断开、重连及控制消息重复。
- 对比 K=1/2/3，验证坏路径不会阻塞健康路径。

通过条件：受控单路径故障时 session 继续工作，去重正确，资源消耗有界。

## 4. 调度与线路验证

- 增加 REPORT、SET、迟滞、分级多发及总发送速率限制。
- 比较不同拥塞控制配置，观察吞吐与小包尾延迟的共同变化。
- 在真实线路验证并确定资源预算与默认参数。

建议压测矩阵：64/256/1200 字节的内层包，K=1/2/3，多种 RTT、随机及突发丢包、带宽不对称、共享瓶颈、单路径黑洞。

## 5. 跨平台与发布

- 接入 Android、iOS、Windows 的 TUN、路由和网络变化事件。
- 验证后台运行、休眠恢复、内存与功耗。
- 补齐安装、配置、升级及诊断文档后发布首个可用版本。
