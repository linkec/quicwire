# quicwire 需求

更新日期：2026-10-02。状态：设计草案，尚未实现。

## 已确定的方向

1. 独立项目，语言使用 Rust，QUIC 库使用 Quinn，异步运行时使用 Tokio。
2. 以本地公私钥及预配置 peer 公钥建立身份，不依赖账号、认证 API 或数据库。
3. 多接入、单核心：客户端同时通过不同边缘连接同一核心。
4. 每条路径是一条独立 QUIC 连接，在应用层绑定为同一 session。
5. 上下行 IP 包都能多发，接收端去重；控制链负责路径绑定、选路和多发份数。
6. 保留标准 QUIC 传输；HTTP/3 网站外观与 MASQUE CONNECT-IP 封装需要单独验证。

## 目标与范围

减少单一路径随机丢包、拥塞和故障造成的业务中断。路径应通过不同 ISP、不同线路或不同接入网络建立；仅改变端口不能证明路径独立。

本期不做带宽聚合，不把内层 IP 数据放入可靠 QUIC stream，不以标准 Multipath QUIC 作为首版依赖。可靠 stream 可以承载控制消息，但控制状态需要跨连接同步。

先以 Linux 两端原型验证网络收益和资源消耗，后续支持 Android、iOS、Windows；各平台 TUN、路由、网络切换与权限集成均需单独实现和验证。

## 术语

| 名称 | 定义 |
| --- | --- |
| Peer | 由公钥识别的对端及其本地授权配置 |
| 客户端 | 接入 TUN，并经多条路径连接核心的程序 |
| 边缘 | UDP 转发节点，不终结 QUIC 连接 |
| 核心 | 终结 QUIC、认证 peer、去重并转发流量的服务器 |
| 路径 | 一条客户端 socket 经边缘到核心端点的 QUIC 连接 |
| Session | 已认证 peer 的一次逻辑隧道会话，包含多条路径 |
| K | 同一个内层包发送的副本数量 |
| 发送集合 | 某方向用于发送副本的路径集合，带 epoch 版本号 |
| 控制链 | 跨可用连接传递认证、绑定、测量和调度信息的逻辑通道 |

## 连接流程草案

1. 两端本地生成密钥，预先配置对端公钥。核心按 peer 配置允许的内层地址、路由、速率和多发上限。
2. 客户端经一条边缘路径建立 QUIC 连接，并完成双向身份验证。私钥持有证明应绑定对端身份、本次握手和连接；具体 TLS 身份绑定与密钥类型待协议规格确定。
3. 核心建立 session，通过加密控制链下发会话绑定材料及该 peer 的地址与路由。
4. 客户端经其他边缘并行建立连接，每条连接验证核心身份后，在 1-RTT 完成后请求绑定已有 session。
5. BIND 证明绑定 session、path_id、双方身份与本连接 TLS exporter；会话绑定材料只在本次 session 内有效。编码、标签、密钥派生及重放防护需在规格阶段审查。
6. 两端确认初始 SET 后传输数据，持续交换 REPORT 与 SET；新路径重复认证及绑定，失败路径摘除。

公私钥配置方式参考 WireGuard，不表示复用其握手或 X25519 密钥格式。首次认证与路径绑定不得使用可重放的 0-RTT 数据。

## 验收边界

- **可靠性**：K ≥ 2，且至少一条已绑定健康路径有足够容量时，单路径故障不应重置逻辑 session；在受控无额外丢包场景验证故障不引入丢包。多路径本身不保证任何网络条件下零丢包。
- **切换**：发送集合切换不能因软件状态更新出现空集合或发送空窗。
- **隔离**：阻塞或填满一条路径队列时，其他路径继续发送，内存保持有界。
- **安全**：拒绝未知公钥、重放认证及跨连接挪用 BIND；撤销 peer 时关闭其已有 session 并拒绝新连接。
- **MTU**：保守配置 TUN MTU，并覆盖 IPv4、IPv6 和路径 MTU 变化；不得把超大包无声丢弃作为完成状态。
- **性能**：量测 K=1/2/3 的 CPU、每秒包数、有效吞吐、P99 延迟、峰值内存；预算在实测后明确。
- **跨平台**：各目标平台验证 TUN 收发、休眠恢复、网络切换和内存使用。

## 技术边界与待决事项

- [ ] 密钥类型、存储格式、TLS 身份绑定、轮替及撤销协议。
- [ ] 控制消息格式、BIND 证明、SET/epoch 语义、session 超时与重连行为。
- [ ] 采用原生 QUIC 应用协议还是 HTTP/3 + MASQUE CONNECT-IP；后者需要补齐 Rust 集成。
- [ ] DATAGRAM 包头格式；若采用 CONNECT-IP，按扩展规则明确 context 与序号封装。
- [ ] 边缘采用 DNAT+SNAT 或带来源信息的 relay；双向路由与源地址可见性需验证。
- [ ] 拥塞控制基线及总发送速率限制，避免多路径共享瓶颈被重复压满。
- [ ] 默认 K、队列字节上限、副本有效期、去重窗口和健康检测参数。
- [ ] IPv4/IPv6 地址、TUN MTU、ICMP、路由和 NAT 方案。
- [ ] SNI、ALPN 及普通 HTTP/3 服务共存方式；标准 QUIC 外观不等于不可识别。
- [ ] 原型通过条件及目标设备资源预算。
